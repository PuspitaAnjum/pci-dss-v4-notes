# PCI DSS Requirement 6
## Develop and Maintain Secure Systems and Software

### Objective

The objective of Requirement 6 is to ensure that systems and software are developed, maintained, and protected using secure processes.

Organizations should identify and address vulnerabilities throughout the software and system lifecycle.

---

## Key Concepts

Requirement 6 focuses on areas such as:

- Secure software development
- Vulnerability management
- Security patches
- Change management
- Secure coding practices
- Web application security
- Software development processes

---

## Vulnerability Identification

Organizations should identify security vulnerabilities in systems and software.

Sources of vulnerability information can include:

- Vendor security advisories
- Vulnerability databases
- Security testing
- Penetration testing
- Internal security assessments
- Threat intelligence

---

## Security Patches

Security vulnerabilities should be addressed through an appropriate patching process.

Organizations should:

- Identify applicable security updates
- Evaluate their impact
- Prioritize critical vulnerabilities
- Apply patches within required timeframes
- Maintain evidence of patching activities

---

## Secure Software Development

Software should be developed using secure development practices.

Examples include:

- Secure coding standards
- Code review
- Developer security training
- Security testing
- Vulnerability remediation
- Separation of development and production environments

---

## Change Management

Changes to systems and applications should follow a controlled process.

A typical change management process includes:

1. Change request
2. Risk assessment
3. Testing
4. Approval
5. Implementation
6. Verification
7. Documentation

---

## Web Application Security

Public-facing web applications require additional security protection.

Organizations should address vulnerabilities such as:

- SQL Injection
- Cross-Site Scripting (XSS)
- Authentication weaknesses
- Access control issues
- Security misconfiguration

Security testing and appropriate technical controls should be implemented according to applicable PCI DSS requirements.

---

## Example Scenario

### Situation

A company discovers a critical vulnerability in its web application.

### Risk

An attacker may exploit the vulnerability to:

- Gain unauthorized access
- Modify application data
- Access sensitive information
- Compromise the cardholder data environment

### GRC Response

The organization should:

- Record the vulnerability
- Assess its risk
- Prioritize remediation
- Apply an appropriate fix
- Test the fix
- Maintain evidence of remediation

---

## GRC / Audit Perspective

An auditor may review:

- Secure development policies
- Vulnerability management procedures
- Patch records
- Code review evidence
- Change requests
- Security testing results
- Developer training records
- Vulnerability remediation records

The key question is:

> Is there evidence that secure development and vulnerability management processes are actually being followed?

---

## Examples of Audit Evidence

- Secure coding standards
- Change management tickets
- Vulnerability scan reports
- Patch management reports
- Code review records
- Security test results
- Developer security training records
- Penetration testing reports

## Interview Questions

### Q1. What is the purpose of PCI DSS Requirement 6?

To ensure that systems and software are developed and maintained securely and that vulnerabilities are identified and addressed.

### Q2. Why is change management important?

It helps ensure that changes are authorized, tested, reviewed, and implemented without introducing unnecessary security risks.

### Q3. Give examples of application vulnerabilities.

Examples include SQL injection, XSS, broken access controls, and security misconfiguration.

---

## Key Takeaways

- Use secure software development practices.
- Identify and remediate vulnerabilities.
- Maintain security patches.
- Follow controlled change management.
- Perform appropriate security testing.
- Train developers on secure development practices.
- Maintain evidence for security assessments.
